# 成功与失败案例分析

## 成功案例

### Success 1: STPS 在 U-trap 中成功逃脱
- **场景**: S1 U-trap, 起点(7.5, 5.0, θ=3.14)面向墙壁
- **行为**: 精确策略πP在U槽内20步后检测到停滞 → 切换到探索策略πE → πE沿U形内壁探索约120步 → 找到开口并驶出 → 切回πP → 到达目标
- **指标**: 步数≈280, 切换1次
- **关键**: 单独使用baseline(πP)在此场景SR=0%，STPS的停滞检测机制使逃脱成为可能

### Success 2: STPS 在窄门场景精确通过
- **场景**: S3 Narrow door, 0.45m开口（机器人直径0.4m）
- **行为**: 精确策略πP从(2.0, 5.0)出发 → 识别到窄门 → 精确对准开口 → 通过 → 到达目标
- **指标**: 步数≈44, 0次切换
- **关键**: 全程未触发切换——精确导航时STPS不干预，与baseline行为完全一致。证明切换机制"不伤害"精确能力

### Success 3: STPS 在标准环境中救回卡住的情况
- **场景**: 标准环境随机障碍
- **行为**: πP导航中遇到两个障碍物形成的凹角 → 停滞 → 切换到πE → 脱困 → 切回πP → 正常到达目标
- **指标**: 100个episode中12次触发切换，11次成功救回
- **关键**: STPS不仅解决设计好的trap场景，在随机障碍中也有价值

## 失败案例

### Failure 1: CNNTD3 Baseline 在 U-trap 中完全失败
- **场景**: S1 U-trap, 所有4个朝向 × 3 seeds = 36次全部失败
- **行为**: 机器人检测到目标在右侧 → 向右移动 → 撞到U形右墙 → 弹回 → 再次向右 → 震荡直到timeout
- **根因**: 标准导航奖励总是引导机器人向目标方向移动，但目标在墙的另一边，需要先远离目标才能到达
- **失败类别**: 策略局限——贪心目标追踪无法产生后退行为
- **教训**: 单纯增加训练时间或调参无法解决，需要根本不同的机制（探索奖励或策略切换）

### Failure 2: Exploration Policy 在窄门中失败
- **场景**: S3 Narrow door, improved(πE) SR=0%
- **行为**: 探索奖励鼓励机器人去没去过的位置 → 接近窄门时位置新颖度为0（已经来过）→ 机器人转向探索两侧空间 → 反复错过窄门开口 → timeout
- **根因**: 探索奖励与精确穿越的行为模式根本矛盾——穿窄门需要"坚定地走已知路线"，探索奖励惩罚这种行为
- **失败类别**: 奖励设计冲突——探索-精确矛盾
- **教训**: 不可能通过调整单一奖励函数同时满足两种需求

### Failure 3: 退火（Annealing）未能兼顾两种能力
- **场景**: v7_finetune, 加载πE权重线性退火探索奖励到0
- **行为**: 随着退火进行，窄门能力逐步恢复（0→100%），但U-trap能力同步丧失（100%→0%）
- **根因**: 探索和精确能力在参数空间中占据不同区域，无法通过连续调参同时保留
- **失败类别**: 优化矛盾——单一策略的参数空间不足以编码两种对立行为
- **教训**: 这个失败直接motivate了STPS——既然参数空间不够，就用两个策略在运行时切换

## 错误分类（Error Taxonomy）

| 类别 | 描述 | 出现在哪 |
|------|------|---------|
| 贪心追踪失败 | 策略永远向目标移动，无法后退 | Baseline在U-trap |
| 奖励设计冲突 | 探索奖励与精确控制不兼容 | πE在窄门 |
| 参数空间不足 | 单一网络无法编码对立行为 | 退火实验 |
| 模型不匹配 | DUNE训练尺寸≠评测机器人尺寸 | NeuPAN 0% |
| 运动学约束不匹配 | MPC输出负速度被裁剪 | NeuPAN倒车问题 |
| 检测延迟代价 | 需要20步才能确认停滞 | STPS的U-trap 75%<πE的83% |
